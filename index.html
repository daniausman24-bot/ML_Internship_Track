Predicting Content Decline to Prioritize Content Review

FlyRank ML Internship Capstone · Lane: Refresh / Content Opportunity Scoring

Abstract

This capstone investigates whether machine learning can identify content that is likely to be declining and help prioritize which content should be reviewed first. A Logistic Regression model was trained using content-performance and engagement features and evaluated using a client-grouped train/test split to reduce client-level leakage. On the held-out test set, the model achieved a Precision@20 of 0.70 and Precision@50 of 0.72, compared with 0.35 and 0.46 respectively for the Week-4 baseline. The model achieved a ROC-AUC of 0.615, indicating moderate predictive separation while showing that the task remains challenging. The resulting predictions were converted into a ranked action playbook containing review priorities and interpretable reason codes.

1. Introduction / Problem Statement

Content teams often have more published content than they can manually review. The practical challenge is therefore not simply determining whether a piece of content is declining, but deciding which content should receive attention first.

This capstone addresses the following decision:

Given a large collection of content, which items should be prioritized for human review because their observed characteristics are associated with content decline?

The project focuses on ranking content for review rather than automatically deciding what action should be taken. The model provides a prioritization signal that can help a content team focus its limited review resources on a smaller set of potentially declining items.

The primary evaluation metric is therefore Precision@K, which measures how many of the highest-ranked items are actually members of the declining class.

2. Data

The analysis uses the FlyRank ML Internship dataset and the provided anonymized content-performance release.

The working dataset contains 30,000 content records and 44 modeling variables after preprocessing. The target variable is is_declining_label, with 16,262 records labeled as declining and 13,738 labeled as non-declining, an overall declining rate of approximately 54.21%.

The analysis uses content-level performance and descriptive variables available in the provided release, including measures related to impressions, clicks, sessions, search position, content age, freshness, word count, content type, and derived tiers. Duplicate records were checked and none were found.

The dataset was divided using a client-grouped split. The training partition contains 23,837 rows from 25 clients, while the test partition contains 6,163 rows from 7 clients. There is zero client overlap between the two partitions. A dedicated leakage audit was performed and passed: the label source (trend_direction), the label itself, and client/content identifiers were excluded from the features.

Because the analysis is based on an anonymized dataset, no client-identifying or otherwise private information is presented in this paper.

3. Methodology

Research Question

Can a simple supervised learning model rank potentially declining content more effectively than the existing baseline?

Target Definition

is_declining_label is binary: 1 = content labeled as declining, 0 = content labeled as non-declining. The model estimates the probability that an item belongs to the declining class.

Features

The model uses numerical and categorical variables describing content performance and characteristics: 90-day impressions, clicks and sessions; average search position; content age; days since update; word count; content type; position, impression, word-count and freshness tiers; and related engagement indicators. Skewed traffic variables are log-transformed (log1p), numeric variables are median-imputed and standardized, and categorical variables are one-hot encoded. All preprocessing is fitted on training data only.

Model

The primary model is Logistic Regression, selected as a simple and interpretable model whose coefficients give directional signals about which features are associated with higher or lower predicted decline probability.

Baseline

The model is compared against the Week-4 rule-based baseline, which sums three flags: stale (at least 180 days since update), visible (at least 500 impressions in 90 days), and weak position (average position of 10 or worse). Both approaches are evaluated on the same held-out test partition.

The primary metric is Precision@K, particularly Precision@20 and Precision@50, because the practical use case is prioritizing a limited number of items for human review. Diagnostic metrics: ROC-AUC, precision, recall, F1, accuracy, and false-positive/false-negative counts.

5. Limitations & Honest Framing

The results should be interpreted as decision-support signals rather than definitive predictions of future content performance.

The model identifies statistical relationships between the available features and the provided declining label. A model coefficient or high predicted probability does not establish that a feature causes content to decline, and nothing here explains how Google's ranking system works.

The ROC-AUC of 0.615 and threshold-based accuracy of 0.58 indicate modest overall classification performance. The model should not be described as highly accurate or as a definitive detector of content decline.

The evaluation uses one client-grouped train/test split with only 7 test clients. Additional validation across different time periods and client groups would provide stronger evidence of generalization. Precision@20 rests on only 20 items, so small changes in the ranking move it noticeably. The test set contains 6,163 keyword-article records, so the observed error rate should not be generalized to other content types.

Finally, a high decline probability does not guarantee that a particular intervention will improve content performance. The recommendations are intended to prioritize human review, not replace editorial or SEO judgment.

6. Ranked Recommendations

Model predictions were converted into a ranked action playbook, ordered by predicted probability of belonging to the declining class. Tiers: ranks 1–20 Priority review; 21–50 Review next; 51–100 Monitor; remaining Lower priority. These thresholds are operational choices, not a universal optimal review budget.

The top 20 items received predicted probabilities between approximately 0.920 and 0.958. Common reason codes include Low CTR, Low engagement, Established search visibility, and Weak average position. Reason codes are rule-based review prompts, not explanations of the model's internal decision for an individual page.
